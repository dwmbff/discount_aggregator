# 7. Соответствие реализации техническому заданию

Источник требований — [техническое задание](technical-specification.md). Статусы:
✅ реализовано в этом репозитории · 🖥 относится к клиентской части (UI) · 🛠 относится к эксплуатации · ⏳ запланировано.

## 7.3 Надёжность и безопасность (п. 8)

| ТЗ | Требование | Статус | Комментарий |
|---|---|:---:|---|
| 8.1 | Доступность 24/7, ИБП, сетевые фильтры | 🛠 | инфраструктура; `/health` для мониторинга |
| 8.2 | Ежедневный бэкап БД и медиафайлов, хранение 30 дней | 🛠 | файлы лежат в одном каталоге/томе (`Storage:Path`, volume `uploads`) — включается в бэкап вместе с БД |
| 8.3 | При недоступности геосервиса — кэш; при подаче заявки — ручной ввод | ✅ | устаревший кэш отдаётся при сбое; без кэша — `503` с предложением ввести данные вручную; заявка подаётся и без геосервиса |
| 8.4 | Лимиты проверяются на уровне БД, а не интерфейса | ✅ | проверка на сервере по данным БД на каждый запрос (счётчик заявок за сутки, дата последнего голоса) |
| 8.4 | Ежемесячная проверка целостности PostgreSQL | 🛠 | регламент эксплуатации |
| 8.5 | Пароли только в виде хеша | ✅ | BCrypt |
| 8.5 | HTTPS | ✅ / 🛠 | `Security:RequireHttps` (HSTS + редирект); в продакшне TLS обычно завершается на reverse-proxy |
| 8.5 | Проверка типа и размера файлов на сервере | ✅ | расширение + сигнатура (magic bytes), ≤ 10 МБ на файл, ≤ 30 МБ на запрос |

## 7.4 Уточнения к ТЗ, принятые при реализации

| № | Неоднозначность | Принятое решение |
|---|---|---|
| 1 | В 5.5 фото подтверждения обязательно, в таблице 5.6 помечено «Нет» | Обязательно (≥ 1 файл); в ТЗ таблица исправлена |
| 2 | Сценарий 5 назван «гость», хотя голосуют авторизованные | Исполнитель — любой посетитель; гость получает предложение войти (401) |
| 3 | Сценарий 3.8: «удаляет заявку» и 5.1: «отменённые заявки учитываются в лимите» | Заявка получает статус `Cancelled`: скрыта от пользователя и модератора, учитывается в лимите |
| 4 | 5.7 №6–7: уведомления об изменении статуса и об актуализации курса | Сервер отдаёт актуальные статусы/курс; показ уведомлений — задача клиента. Push/email-рассылка — в roadmap |
| 5 | Версия платформы в ТЗ — ASP.NET Core 8 | Реализовано на .NET 9; в ТЗ значение обновлено |
| 6 | Скорость и нагрузка (100 пользователей, отклик ≤ 3 с) помечены в ТЗ вопросом | Нагрузочное тестирование не проводилось; требование оставлено как целевое |
